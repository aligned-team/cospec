# Proposal

## Why

CI installs whatever mise is newest (`jdx/mise-action` with no `version`), while
`mise.toml` only sets a floor (`min_version`). mise releases write different
lockfile metadata and even resolve different assets, so `mise.lock` drifted with
each mise release and the drift gate broke on every branch when v2026.11.9
shipped — and #108 then matched the lockfile to that release rather than to
`min_version`. Separately, the change detection never listed `mise.lock`, so a
lockfile-only change skipped the drift gate entirely.

## What Changes

- `.github/actions/setup-mise/action.yml`: read `min_version` from `mise.toml`
  and pass it to `jdx/mise-action` as `version`, so CI's mise is that release by
  construction and can never drift from it.
- `scripts/mise-tasks/lock` with tasks `lock` / `lock:check` in `mise.toml`:
  download the `min_version` mise release (checksum-verified against its
  `SHASUMS256.txt`), and run its `mise lock` with isolated data, cache, state
  and config dirs and its hooks off — in place, or on a scratch copy to compare.
  `mise lock` can exit 0 after failing to resolve an entry, so a run fails on
  any warning or error it logs or an entry it skipped. `lock:check` joins
  `mise run check`.
- `.github/workflows/ci.yml`: the mise lockfile drift gate runs
  `mise run lock:check` (exactly `min_version`'s `mise lock` output for every
  platform) instead of `mise install` plus a diff; `mise.lock` joins every path
  filter that lists `mise.toml`; the shellcheck step covers the new script.
- `mise.lock`: regenerated by mise 2026.7.7 (`min_version`).
- `.agents/shared.md` (synced into `CLAUDE.md` / `AGENTS.md`) and
  `CONTRIBUTING.md`: the rule, and the two tasks.

## Impact

- Every workflow's mise (CI, PR title, release) is `min_version`; bumping
  `min_version` means `mise run lock` in the same commit.
- A lockfile-only change now runs `ci-bun` (and its drift gate), `ci-docs`, and
  the canon and openspec jobs. Required checks are unchanged.
- `mise run check` and the drift gate download one mise binary on first use
  (cached under `${XDG_CACHE_HOME:-~/.cache}/cospec-dev/`) and query release
  metadata over the network.
