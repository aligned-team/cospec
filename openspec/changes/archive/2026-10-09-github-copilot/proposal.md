# Proposal

## Why

`github-copilot` is one of the pinned OpenSpec 1.13.1 binary's tool ids, and
`cospec init --harness github-copilot` refuses it today as an unknown harness: a
repo that uses GitHub Copilot in an editor gets no cospec skills, no slash
prompts, and no detection on `cospec update`. The binary also ships the one
piece of tool setup that is not a skill or a command, the opt-in **cloud
agent**: `openspec init --copilot-cloud` writes a GitHub Actions workflow
(`.github/workflows/copilot-setup-steps.yml`) and a custom-agent profile
(`.github/agents/openspec.agent.md`) so that the GitHub-hosted Copilot coding
agent can run the CLI in its ephemeral environment. cospec has neither the
target nor the opt-in, and its command table rejects both `--copilot-cloud` and
`--no-copilot-cloud` as "not supported yet".

This change is roadmap PR R10 (row 53, owner slug `github-copilot`). It lands
after `tool-matrix` (R9), which turns the closed four-tool union into the full
tool matrix. Here `github-copilot` is one more row in that table, with a
`.prompt.md` command surface, plus the cloud-agent opt-in: the flag pair, a
five-tier decision ported verbatim from the pinned binary, a persisted
`githubCopilot.cloudAgent` key, two managed files that cospec only ever removes
when it wrote them, removal on opt-out, and re-sync on `update`.

## What Changes

- **A `github-copilot` harness row**, between `gemini` and `hermes` in
  `HARNESS_TABLE` (upstream's `AI_TOOLS` order):
  - Skills under `.github/skills/cospec-<skill>/SKILL.md`.
  - Commands as `.github/prompts/cospec-<command>.prompt.md` (flat, `/` prefix,
    `description` frontmatter plus cospec's provenance block).
  - Seven detection paths, verbatim from upstream:
    `.github/copilot-instructions.md`, `.github/instructions`,
    `.github/workflows/copilot-setup-steps.yml`, `.github/prompts`,
    `.github/agents`, `.github/skills`, `.github/.mcp.json`.
  - `requiresIdeRestart: true`, so the receipt ends with upstream's
    `Restart your IDE to refresh commands.`
  - Upstream's pre-opsx `.github/prompts/openspec-*.prompt.md` path joins the
    leftover scan, as R9 leaves it to this change.
- **`init --copilot-cloud` / `--no-copilot-cloud`**, handled instead of pending.
  The decision follows upstream's five tiers in upstream's order (design,
  decision 1): the flag, the persisted `githubCopilot.cloudAgent`, managed files
  already on disk, an interactive confirm, then "skip, persist nothing". Only a
  flag or an answered confirm persists. When the flags are passed without
  `github-copilot` selected, init prints upstream's one-sentence notice and
  carries on.
- **`githubCopilot.cloudAgent` in `openspec/config.yaml`**, a boolean, written
  through the YAML document model so the file's comments and order survive.
- **Two managed cloud files**, authored in cospec's canon and naming `cospec`,
  not `openspec`:
  - `.github/workflows/copilot-setup-steps.yml` installs `@aligned-team/cospec`
    and runs `cospec --version`.
  - `.github/agents/cospec.agent.md` is the custom agent, with `metadata`
    provenance in its frontmatter. Each carries a visible "Generated by cospec"
    marker. A file cospec did not write, or wrote and you then edited, is never
    removed and never overwritten.
- **`cospec update` re-syncs the cloud files on every run** while opted in,
  removes the managed ones on an explicit opt-out, and removes them when
  `github-copilot` is no longer a configured harness. `update --check` and
  `cospec doctor` report the same drift without writing.

**BREAKING:**

- `openspec/config.yaml` is no longer "never touched by cospec": `cospec init`
  adds or updates exactly one key, `githubCopilot.cloudAgent`, when the opt-in
  is decided by a flag or an answered prompt. Every other byte, comment and key
  order stays. The Configuration page's "never touched" sentence changes with
  it.
- `.github/` becomes a directory cospec owns managed files under: `init`,
  `update`, `update --check` and `doctor` now read and may remove cospec-written
  files below it (the skills, the prompts and the two cloud files).
  `--harness all` selects `github-copilot`, so its receipt, its JSON `harnesses`
  array and the `Restart your IDE to refresh commands.` line change.
- `cospec init --copilot-cloud` and `--no-copilot-cloud` stop failing with
  `'<flag>' is not supported yet` (exit 1) and start acting; `--help` and the
  completion specs list them.
- A repo that already has OpenSpec's `.github/workflows/copilot-setup-steps.yml`
  keeps it: cospec reports it as a file it did not write and writes its own
  version beside it as `copilot-setup-steps.yml.cospec-new`.

## Capabilities

### New Capabilities

- `copilot-cloud-agent`: the opt-in for GitHub Copilot's cloud coding agent: the
  flag pair, the five-tier decision, the persisted `githubCopilot.cloudAgent`,
  the two managed files and what makes one managed, removal on opt-out, re-sync
  and removal on `update`, and the notice for a flag passed without the tool.

### Modified Capabilities

- `harness-workflows`: gains the requirement that `github-copilot` is a harness
  target (paths, dialect, detection, restart line, legacy prompt path), and
  modifies "Every pinned tool id is a harness", which `tool-matrix` archived
  with `github-copilot` as its one exclusion, to accept every id.

## Impact

- `apps/cli/src/harness/adapters.ts`: one `HARNESS_TABLE` row, and the row field
  `tool-matrix` adds for upstream's `LEGACY_SLASH_COMMAND_PATHS` carries the
  `github-copilot` entry.
- `apps/cli/src/canon/github-copilot/` (new) and `src/canon/embedded.ts`: the
  two cloud templates, embedded for the compiled binary.
- `apps/cli/src/harness/copilot-cloud.ts` (new): the pure pieces: templates, the
  managed check, `githubCopilot.cloudAgent` read and persist.
- `apps/cli/src/commands/init.ts`: the flag pair, the tier decision, the
  persisted write, the notice, the receipt lines and the `--json` key.
- `apps/cli/src/commands/update.ts`: `generate()` emits and removes the cloud
  files; `update` prints the hint and the left-in-place lines.
- `apps/cli/src/core/command-table.ts` and
  `apps/cli/test/contract/parity-pending.yaml`: the two flags leave the pending
  list; the parser reports which of the pair came last.
- Tests: `test/contract/copilot-cloud.test.ts` (new) holds the precedence matrix
  against the pinned binary; unit, integration and the pack smoke cover the
  rest. Four existing tests that assert the flags are pending change.
- Docs: `apps/docs/guide/harness-setup.md`,
  `apps/docs/reference/configuration.md` (owns `githubCopilot.cloudAgent`) and
  the `init` row of `apps/docs/reference/commands.md`, plus `.agents/shared.md`
  with `mise run agents:sync`.
