# Proposal

## Why

Bun 1.4.3 ships a built-in type checker (`bun check`, a port of typescript-go
that passes TypeScript 7.0.2's conformance suite) and Bun 1.4.4 a built-in
formatter (`bun fmt`, configured in `bunfig.toml`'s `[fmt]`), so moving from Bun
1.3.14 to 1.4.4 lets the repo drop two separately pinned tools and their config
files. This is a toolchain migration only: no feature, CLI, schema or
user-facing behavior changes.

## What Changes

- `mise.toml`: `bun` 1.3.14 → 1.4.4; drop the `npm:@typescript/native-preview`
  (`tsgo`) and `npm:oxfmt` pins; `typecheck` runs `bun check`, `format:check` /
  `format:fix` run `bun fmt`. oxlint stays: Bun's docs describe a `bun lint`,
  but Bun 1.4.4 has none (`bun lint` outside a project answers
  `Script not found "lint"`).
- `bunfig.toml`: a `[fmt]` section carries every option `.oxfmtrc.json` set
  (style options, `sortPackageJson`, `[fmt.sortImports]`, the four
  `[[fmt.overrides]]`) plus `.prettierignore`'s patterns as `ignorePatterns`,
  and `flavor = "oxfmt"` so the output stays oxfmt's, not Prettier's.
  `.oxfmtrc.json` and `.prettierignore` are deleted. The `verification.md`
  override is spelled without a slash so it matches the file name anywhere, a
  scratch copy outside the repo included.
- `mise.lock`: Bun 1.4.4 checksums for every locked platform; the stale `tsgo`
  and `oxfmt` entries pruned.
- `package.json` (root, private): `bun-types` 1.4.4 and `engines.bun` `>=1.4.4`
  (the first release with `bun fmt`). `apps/cli/package.json` and
  `packages/bench/package.json`: `bun-types` 1.4.4, `typecheck` script
  `bun check`.
- `bun.lock`: regenerated by Bun 1.4.4 — the `bun-types` bump plus 1.4.4's
  hoisting of `picomatch` (same resolved versions); `lockfileVersion` stays 1.
- `hk.pkl`: the formatter step runs `bun fmt`.
- `scripts/mise-tasks/agents/sync` and `scripts/mise-tasks/release/set-version`
  normalise with `bun fmt --cwd=<repo root>`: `bun fmt` finds `[fmt]` from the
  working directory up, and both format a file outside the repo.
- `.github/workflows/ci.yml`: the `bun` path filter watches `bunfig.toml` in
  place of `.oxfmtrc.json`.
- `apps/cli/src/vendor/openspec.bundle.js.tpl`: regenerated with
  `mise run vendor:openspec` — the bundle is byte-deterministic per Bun version.
- Formatting churn, no semantic change: the five files where `bun fmt` and oxfmt
  0.56 disagree on layout (two contract tests, one docs page, two archived
  change documents), and the 75 files whose named imports `[fmt.sortImports]`
  re-sorts — Bun sorts the names inside `{ }`, which the `.oxfmtrc.json`
  `sortImports` did not, and has no option to leave them.
- `apps/cli/test/integration/verification-format.test.ts` runs `bun fmt` instead
  of the oxfmt binary, with a control case proving the config applied.
- `packages/bench` `perf` and `perf-hard` scenarios: Bun 1.4.4's JIT runs the
  seeded nested-loop `dedupe` about 13x faster, so it cleared its speed
  thresholds and the scenarios no longer told "not done" from "done". The
  `dedupe` input sizes in `bench/measure.ts` and the hidden suites are raised
  (thresholds unchanged), restoring a 4-7x margin on the slow side.
- `apps/cli/test/fixtures/support.ts`: since Bun 1.4 `process.env` behaves like
  Node's, so a `process.env.TZ` a suite assigned now survives
  `{ ...process.env }`, and deleting it moves the suite onto the machine's zone.
  `envWithoutColorForcing()` — the base of every test sandbox env — drops `TZ`,
  keeping the "the sandbox env carries no TZ" invariant its unit test guards;
  that test now assigns `TZ` first, and the comments that described Bun 1.3's
  behavior are corrected.
- Contributor docs and comments that name the old tools or config files:
  `.agents/shared.md` (synced into `CLAUDE.md`/`AGENTS.md`), `CONTRIBUTING.md`,
  `hk.pkl`, the release workflow, test helpers and bench READMEs; two comments
  that cite "Bun 1.3.14" behavior re-verified on 1.4.4.
- Unchanged by design: the `cospec init --gate` templates
  (`apps/cli/src/canon/gate/hk.pkl.tpl`, `mise.toml.tpl`) keep writing oxlint +
  oxfmt into users' repos — that is product behavior, not this repo's tooling.

## Impact

- Local dev and CI: `mise install` fetches Bun 1.4.4; `mise run typecheck`,
  `mise run format:*` and the pre-commit/pre-push hooks use Bun's built-ins.
  CI's mise lockfile drift gate and `bun install --frozen-lockfile` read the
  regenerated lockfiles.
- Release: the seven cross-compiled standalone binaries are built with, and
  embed, Bun 1.4.4's runtime; the vendored openspec bundle is rebuilt by Bun
  1.4.4's bundler.
